## Contexte

Le dégroupage fonctionne correctement côté Core, mais un bug apparaît lorsqu’un groupe initialement ancré à une balise est scindé.

Exemple fonctionnel :

* le groupe courant est ancré à une balise via T1 ;
* on déclenche `Dégrouper` à un endroit plus loin dans la chaîne, par exemple T11 ;
* `TopologyWorld.degrouperAtNode(...)` produit correctement plusieurs groupes ;
* l’un des groupes résultants conserve la `GroupAnchor` ;
* l’UI applique ensuite son petit décalage visuel automatique post-dégroupage ;
* ce décalage passe aujourd’hui par `TopologyWorld.move_group(...)` ;
* si le groupe à décaler est précisément le groupe qui conserve l’ancre, le Core refuse légitimement le MOVE.

Erreur observée :

```text
ValueError: TopologyWorld: MOVE interdit pour le groupe ancré 'G033' (ancre AN001)
```

Le Core est correct et ne doit pas être assoupli.

## Zone concernée

Principalement :

```text
src/assembleur_tk.py
```

Méthodes concernées :

```python
_ctx_degrouper()
_applyDegrouperResultToTk()
_move_core_group_by_screen_delta()
```

Le chemin actuel est :

```text
_ctx_degrouper()
    ↓
world.degrouperAtNode(...)
    ↓
_applyDegrouperResultToTk(...)
    ↓
layout visuel post-dégroupage
    ↓
_move_core_group_by_screen_delta(...)
    ↓
world.move_group(...)
```

Aujourd’hui `_applyDegrouperResultToTk()` suppose implicitement que les groupes contenus dans `newGroupIds` peuvent être déplacés pour le layout visuel.

Cette hypothèse est fausse : après le dégroupage, un `newGroupId` peut être le groupe qui conserve la `GroupAnchor`.

## Contrat fonctionnel attendu

Après un dégroupage d’un groupe ancré :

1. identifier les groupes Core résultants ;
2. déterminer lesquels possèdent une `GroupAnchor` via l’API Core existante ;
3. tout groupe ancré doit rester strictement immobile ;
4. le petit décalage automatique de séparation visuelle ne doit s’appliquer qu’aux groupes non ancrés ;
5. le groupe contenant encore T1 / le propriétaire physique de la balise reste donc exactement en place ;
6. peu importe qu’il soit retourné comme `mainGroupId` ou comme membre de `newGroupIds`.

La notion pertinente est :

```text
groupe ancré
vs
groupe non ancré
```

et non :

```text
mainGroupId
vs
newGroupIds
```

## Contrat Core à préserver

NE PAS modifier :

```python
TopologyWorld.move_group(...)
TopologyWorld._reject_transform_of_anchored_group(...)
```

L’interdiction d’un MOVE sur un groupe ancré est un invariant volontaire et correct.

NE PAS ajouter de fallback qui contournerait cette interdiction.

NE PAS détacher automatiquement la balise.

NE PAS faire de `try/except` autour de `move_group()` pour ignorer l’erreur.

Le correctif doit éviter l’appel invalide, pas masquer l’exception.

## Implémentation attendue

Dans `_applyDegrouperResultToTk()` :

* conserver la reconstruction/projection Core actuelle ;
* lors du layout visuel post-dégroupage, tester explicitement :

```python
world.getAnchorForGroup(core_gid)
```

avant tout appel à :

```python
_move_core_group_by_screen_delta(...)
```

Si le groupe est ancré :

```text
ne pas le déplacer
```

Si le groupe n’est pas ancré :

```text
le comportement historique de décalage visuel peut être conservé
```

Attention : ne pas limiter la logique à `newGroupIds`.

Le groupe fixe doit être déterminé selon la présence réelle de la `GroupAnchor`.

Si nécessaire pour conserver un layout cohérent, le groupe ancré peut servir de référence fixe pour les calculs de séparation visuelle.

## Tests à ajouter

Ajouter des tests ciblés couvrant au minimum :

### Cas 1 — groupe non ancré


### Cas 2 — groupe ancré, groupe ancré = mainGroupId

```text

```

### Cas 3 — groupe ancré, groupe ancré dans newGroupIds

Cas reproduisant le bug observé :

```text
groupe initial ancré via T1
dégroupage plus loin, par exemple au niveau de T11
le groupe résultant contenant T1 conserve l’ancre

```

Vérifier :

```text

aucune exception
groupe ancré inchangé
autres groupes décalés si nécessaire
```

### Cas 4 — invariant Core

Vérifier qu’un appel direct volontaire à :

```python
world.move_group(anchored_group_id, ...)
```

continue bien d’être refusé.

Le fix UI ne doit surtout pas affaiblir ce comportement Core.
